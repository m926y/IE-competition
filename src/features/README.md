## 时间窗口与划分

主窗口为6月1—21日特征，6月22日—7月31日40天标签。
辅助窗口为过去14/21/30天预测后续14天，截止日每7天滚动，并加入7月17日终端截止窗口。
额外增加6月17—30日特征、7月1—14日标签的验证窗口，避免验证标签与最后测试标签重叠。
原16个窗口保留，增加验证窗口后共17个。

固定14天时间验证实验：

1. model_selection：训练特征6月1—14日，标签6月15—28日；验证特征6月17—30日，标签7月1—14日。
2. locked_test：冻结特征、超参数和阈值后，可使用14天特征且标签截至7月17日已可知的窗口重训；测试特征7月4—17日，标签7月18—31日。
3. 模型选择完成前禁止读取最后测试窗口的指标进行调参。数据已交付不代表代码能阻止人为调参，B 需遵守约定。
4. 允许同一车辆跨时间进入训练和测试，因为比赛预测同一批车辆未来风险；gpsno 不入模。窗口重复不能当作独立车辆，禁止随机行拆分。
5. 训练标签结束日必须不晚于验证/测试特征截止日。滚动窗口可以共享历史，但不得使用预测时点以后的标签。

61天数据不足以支持“在6月21日前用完整14+14样本训练，再独立测试未来40天”。主40天窗口仍按要求生成，标记 main_40d，作为诊断样本，不混入固定14天的严格时间验证。
30天特征的可训练历史更少，因此不提供虚假的30天独立训练/验证/测试分割；需单独设计实验或仅作为候选特征。
最终比赛预测期为8月1日至9月9日40天，没有对应真值。14天模型输出不能直接宣称是校准后的40天概率；期限迁移由 B 负责并记录假设。

## 特征口径

- `_window` 表示该行 feature_start 到 feature_end；最终表对应61天，训练表对应14/21/30天。
- `_14d` 是严格的最后14天；近期7/14/30天统计历史不足时保持 NULL，不越过 feature_start。
- 核心模型只使用相同长度的14天或7天统计及7对7趋势。不能将训练期21天计数替换为61天计数。
- 保留完整候选表，供 C 使用全窗口统计、B 做分组消融。字典 window_days=feature_window 时，实际长度取该行 feature_window_days。
- 所有事件按 event_type 编码计数。日表0表示未记录事件，不表示已证实安全。无独立司机ID，gpsno仅作连接键。
- 活跃天数定义为轨迹 moving_rows>0 的日期数；覆盖天数定义为有相应数据源记录的日期数；两者不等同。
- 里程单位km、运行时长单位小时。比率分母为0或缺失时为NULL，绝不填0。清洗层运行时长的业务口径未重新推定为驾驶时长。
- 衰减权重为2^(-age_days/14)。近期性只查当前特征期，没有历史记录时为NULL，并输出 has_history；这是左删失，不代表终生无事故。
- 连续风险天数基于完整日历。峰值小时占比是按每天钟点合并后的24小时桶最大次数/事件数。
- 前后5分钟预警统计仅配对历史事故/未遂和非高危事件，两端均位于特征期；一条预警可与多个高危事件配对，故名称是配对数，不是去重事故数。
- 轨迹均速及标准差用有效速度点数和二阶矩合并。日里程/时长波动只统计已观测日，不把未观测日当停车日。
- IMU 缺失保留 NULL和覆盖率。异常阈值沿用清洗层，只是候选标志。单轴不假定车辆方向，首版核心优先使用模长。
- IMU 日表没有每个轴/速度差的有效点数，输出 daily_mean 是非空日统计的等权平均，不冒充全窗口逐点均值/标准差。
- 画像的半年统计截至7月31日（答疑已确认），相对于早期回测含未来信息，原值保留供审计，严格核心暂时排除全部画像快照特征（包含能源类别，保守一致处理）。

## 约100维首版模型与训练折拟合

候选表保留稀有事件、长窗口统计和缺失标志，因此可能有常量、完全重复或训练早期全空的列。这些是供审计的字段，不属于正式入模集合。
FoldFeatureSelector 只在 model_selection 的训练窗口（6月14日截止）上拟合：删除全空和常量，删除完全重复及绝对相关系数>=0.995的冗余列，然后最多选100列。业务顺序为暴露、质量、轨迹、事件维度、事件类型、聚集性、IMU、近期次数、趋势按轮次交替提名，避免固定截取前100列遗漏后面的特征族；顺序不使用标签或验证指标。
相关性计算临时使用训练中位数，导出的值不填补；训练中位数不作用于验证/测试表。未使用验证/测试或最终61天的分布选列。
两张 core 表和 core_model_features.json 是满足“无训练全空/常量/重复列、约100维”的正式模型接口；日期/窗口和 gpsno 元数据必须排除。
实际核心维数由训练数据决定，不为凑100保留冗余特征。其他窗口实验应在相应训练折重新拟合，且不能用测试反馈修改冻结模型。

ExposureShrinker 提供 fit/transform：mu=训练事件总数/训练暴露总量；tau 默认取正暴露的训练中位数，是明确的经验先验强度启发式，并非最大似然估计。
收缩率=(n+tau*mu)/(exposure+tau)。缺失/零暴露保持 NULL。应在每次训练折内拟合，只向验证/预测应用训练参数。A 不用全数据预先生成有泄漏风险的收缩列。
中位数填补、截尾、标准化、类别编码、模型选择和40天概率处理由 B 在训练管道负责。

## 验收及限制

自动检查500车集合、唯一键、17个窗口行数、事件计数守恒、标签独立SQL重建、日期边界、比率分母、无无穷值、Parquet回读和输入指纹。
主窗口正类车辆与前次独立统计的55辆核对。
真实数据删除截止日后的全部日记录后，重算早期特征应不变；最终61天表中的核心列需与独立14天窗口逐值一致。
合成测试额外覆盖边界第一秒/最后一秒、历史高危特征、短时预警跨截止日、未来传感器值注入、零分母、IMU缺失、合并方差和先验训练隔离。
机器测试和数据检查通过代表 A 接口与计算验收通过，不代表 B 模型AUC、比赛40天概率或 C 评分已验证。
